88초를 13초로, 오전 반나절을 알림 한 통으로

기술보다 먼저 보는 것: 그 기술을 쓰는 사람의 시간

일을 판단할 때 저는 "이 기술이 누군가의 시간을 얼마나 줄여주는가"를 먼저 봅니다. 화려한 기능보다, 매일 같은 일을 반복하는 사람의 하루가 조금 가벼워지는 변화에 더 큰 보람을 느껴 왔습니다. 이 기준은 제가 맡은 자리가 개발 직무가 아닐 때에도 같았습니다.

직무 밖의 문제를 직접 풀어본 경험

스타트업에서 사업운영 업무를 맡았을 때, 담당자는 매일 오전의 절반을 나라장터 공고를 검색하고 하나씩 열어보는 데 쓰고 있었습니다. 저는 이 과정을 "빠짐없이 찾기, 관련성 판단, 꼭 필요한 것만 받기"라는 요구로 나누고, Open API 조회와 Claude 기반 적격 판정, 점수 기준 선별, 메신저 알림으로 이어지는 시스템을 직접 만들었습니다. 운영하면서 실행 시간이 88초까지 늘어나자, 대부분이 외부 응답을 기다리는 시간이라는 점을 확인하고 호출 한도 안에서 병렬화해 13초로 줄였습니다. 그 결과 담당자는 아침에 도착한 알림만 확인하면 되었습니다. 맡은 범위를 넘더라도 반복되는 불편을 그냥 두지 않는 것, 그것이 제가 일하는 방식입니다.

규칙이 엄격한 곳에서 배운 정확함

현재는 금융정보분석원(FIU) 정보시스템의 유지보수와 운영을 맡고 있습니다. 데이터가 쌓일수록 느려지던 대민 게시판을 서버 페이징 방식으로 바꾸었고, SSL 인증서 교체와 웹 접근성 인증 대응도 진행하고 있습니다. 금융권 시스템은 작은 수정도 담당 주무관과의 협의, 테스트 산출물, DBA·AA 대상 배포요청서, 형상관리 통제를 거쳐야 반영됩니다. 처음에는 절차가 번거롭게 느껴졌지만, 이 과정이 서비스를 믿고 쓰는 사람들에게 주는 안정감이라는 것을 알게 되었습니다. 이곳에서 빠르게 고치는 것보다 정확하게 고치는 것이 더 큰 신뢰를 만든다는 점을 배우고 있습니다.

다른 의견 앞에서 먼저 묻는 것
