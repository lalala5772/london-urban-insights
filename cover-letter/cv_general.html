#문제해결
1엑셀 업로드 장애 — '서비스 로직 오류'로 보였으나, 파일 서명(PK / D0CF11E0) 확인 결과 기관 PC의 DRM 암호화 파일을 서버(Apache POI)가 읽지 못하는 것이 원인파일 업로드를 엑셀 복사·붙여넣기 → 미리보기 → 반영 로직으로 리팩토링. DRM 해제 없이 동작하고, 기존의 '전체 삭제 후 재등록' 대신 추가 / 해당 연도만 교체 방식으로 변경
2여러 행 CRUD 처리 로직 부재 — 한 건씩만 저장되고, 순번이 DB 값 기준으로 매겨져 화면 순서와 어긋남여러 행의 추가·수정·삭제를 한 번에 처리하는 서비스 로직 추가. 연도 단위 단일 트랜잭션(오류 시 전체 롤백), 화면 순서 기준 순번 자동 부여, 논리 삭제
3매퍼 필수 컬럼 누락 — 등록자 ID 등 NOT NULL 컬럼이 쿼리에 빠져 등록이 실패하고, 일련번호 자료형이 쿼리마다 달랐음MyBatis 매퍼 수정 — 누락 컬럼 반영, 자료형 통일, 다건 처리 쿼리 추가, 모든 값을 바인딩 변수로 처리
4XSS 위험 — 연혁 텍스트 입력값에 넣은 스크립트가 대민 화면에서 그대로 실행됨XSS 이스케이프 함수를 추가해 대민 화면(국문·영문) 출력 시 적용, 관리자 화면은 텍스트로 출력

테스트 · 반영 — 기존 URL·쿼리 ID와 대민 화면 호출 형태를 유지해 영향 범위를 줄이고, 개발 서버에서 7단계 기능 시험(다른 메뉴 영향, 데이터 정합성, 트랜잭션 롤백 포함)을 거쳐 실서비스 운영 환경에 적용. 담당 주무관은 한 건씩 입력하던 연혁을 표 편집과 붙여넣기로 한 번에 등록

1사람의 말에서 일을 찾는 성격

저는 사람을 만나 이야기 나누는 것을 좋아하는 밝은 성격입니다. 고객 응대를 하던 시절에도, 고등학교에서 디지털 튜터로 학생들의 기기와 수업을 돕던 시절에도 먼저 다가가 "어디가 불편하세요?"라고 묻는 것이 자연스러웠습니다. 그렇게 들은 이야기에는 늘 고칠 수 있는 무언가가 들어 있었고, 저는 그것을 기술로 풀어내는 일에서 가장 큰 재미를 느낍니다.

2사업을 알고 나니 기술이 다르게 보였습니다

스타트업에서 사업운영 직무로 공공기관 대상 B2G 사업을 맡았을 때, 가장 먼저 눈에 들어온 것은 반복 업무였습니다. 담당자는 매일 오전의 절반을 나라장터 공고 검색에 쓰고 있었고, 입찰이나 지원사업 서류를 낼 때마다 같은 회사 정보를 손으로 다시 입력하고 있었습니다. 저는 Claude 기반으로 적격 공고만 골라 알려주는 시스템을 만들어 실행 시간을 88초에서 13초로 줄였고, 회사 정보를 자동으로 채워 주는 OA 툴을 Spring Boot로 개발해 사내 시스템으로 쓰도록 했습니다. 그렇게 확보한 시간으로 입찰 PT 자료를 만들고, 자사 솔루션을 공부해 여러 정부지원사업 제안서를 작성했습니다. 체결된 사업의 수행 미팅에도 직접 참여하며 공공 사업이 어떤 절차로 진행되는지 배웠고, 참여 인력들과 소통해 e-나라도움으로 인건비를 집행하는 일까지 맡았습니다. 공고를 찾는 일부터 돈이 집행되는 순간까지 사업의 전 과정을 보고 나니, 기술이 어디에 쓰여야 실제로 도움이 되는지가 훨씬 선명해졌습니다.

3점검에서 찾은 문제를 먼저 제안하고, 운영까지 반영하다

금융정보분석원(FIU) 정보시스템의 일일 점검 중, 대민 홈페이지에 게시되는 기관 연혁의 관리 기능에서 여러 문제가 겹쳐 있는 것을 발견했습니다. 엑셀 업로드는 서비스 로직 오류처럼 보였지만, 파일 서명을 확인해 보니 기관 PC의 문서보안(DRM) 암호화 파일을 서버가 읽지 못하는 것이 원인이었습니다. 여기에 여러 행을 한 번에 처리하는 로직이 없었고, 매퍼에는 필수 컬럼이 빠져 있었으며, 연혁 입력란에 넣은 스크립트가 대민 화면에서 그대로 실행되는 XSS 위험도 있었습니다. 저는 문제와 해결 범위를 정리해 SR 할당을 먼저 요청했고, 업로드를 붙여넣기 방식으로 리팩토링하고, 다건 처리 서비스 로직과 매퍼를 고치고, 출력 시 이스케이프 함수를 적용했습니다. 기존 호출 구조를 유지해 영향 범위를 줄이고 개발 서버에서 단계별로 시험한 뒤 실서비스에 반영했습니다. 이 경험을 통해, 맡은 일만 처리하는 데서 그치지 않고 먼저 문제를 찾아 제안하는 것이 운영을 맡은 사람의 역할이라는 것을 배웠습니다.

4신입의 속도와 경력의 시야를 함께

저는 아직 배울 것이 많은 신입입니다. 그래서 모르는 것은 바로 묻고, 배운 내용은 블로그에 정리하며 빠르게 따라잡으려 합니다. 동시에 사업운영과 공공 시스템 운영을 거치며 고객이 무엇을 원하는지, 어떤 절차를 거쳐야 서비스가 바뀌는지를 현장에서 익혔습니다. 신입의 에너지와 실무에서 얻은 사업 감각을 함께 가진 것이 저의 가장 큰 강점이라고 생각합니다.

5입사 후, 듣고 정리하고 만드는 사람으로

소프트웨어 엔지니어링, 웹 개발, AI 솔루션, IT 컨설팅 중 어떤 자리에서든 제가 일하는 순서는 같습니다. 먼저 사용하는 사람의 이야기를 듣고, 문제를 구조로 정리해 제안하고, 직접 만들어 반영하는 것입니다. 입사 후에는 팀과 고객 사이에서 밝은 에너지로 대화를 이끌고, 작은 불편도 놓치지 않는 제안으로 함께 일하는 사람들의 시간을 아껴 드리겠습니다.
